Clasificación y medición del desempeño

Author

Guillermo Ruiz

Clasificación de texto binaria

La categorización de documentos o clasificación de documentos consiste en ordenar un conjunto de documentos en categorías o clases previamente definidas.

Los documentos pueden ser desde textos cortos como tweets hasta documentos largos como artículos o libros completos. Tradicionalmente, la tarea de categorización es realizada por personas expertas en el dominio de aplicación. Sin embargo, con las grandes cantidades de información que se generan diariamente es necesario usar métodos que clasifiquen automáticamente la información.

Desde el punto de vista del aprendizaje computacional, es prometedor aprender el esquema de categorización por medio de ejemplos de entrenamiento. Una vez aprendido el esquema de categorización (modelo de predicción), éste se puede usar para clasificar futuros documentos. Existen diversos enfoques para atacar este problema como es el uso de modelos bayesianos, árboles de decisión, programación evolutiva, redes neuronales, métodos de kernel, entre otros.

En general, un método de aprendizaje supervisado realiza los siguientes pasos: 1. Preprocesamiento de los documentos, como limpieza y estandarización. 2. Calcular las probabilidades o transformar los datos crudos (documentos) a una forma computable, por ejemplo, la vectorial. 3. Aprender de los datos asociando los documentos a las categorías definidas en el conjunto de entrenamiento. 4. Predecir nuevos datos que sirven de validación del método, es decir, que tan bien se desempeña con los datos de prueba o datos nuevos.

En el caso del preprocesamiento, se pueden obtener n-gramas de palabras o caracteres o combinaciones de estos, como características del documento. También se realizan los procesamientos típicos como usar sólo letras minúsculas, eliminar puntuación o símbolos raros, eliminar stopwords, utilizar procesos de stemming o lematización, todo esto con el fin de reducir el vocabulario y que términos con varias formas (rojo, rojas, rojos, rojas) se puedan mapear a un mismo término (roj-) y que haya más emparejamientos entre características.

Para crear el modelo de predicción, se usan los ejemplos de entrenamiento y su categoría asociada, la cual fue asignada por un experto humano. De ahí que el conjunto de datos puede tener un sesgo debido a la subjetividad intrínseca del conjunto de entrenamiento.

En el caso de reseñas u opiniones es típico usar categorías como positivo, negativo o neutro para categorizar estos textos cortos.

Por ejemplo:

  • “Me gustó la comida del restaurante X” (positivo)
  • “El servicio de internet fue pésimo en el hotel” (negativo)

La clasificación automática de documentos es un paso importante para la toma de decisiones basada en conocimiento. Por ejemplo, si una persona desea comprar un producto (celular, computadora, lavadora, etc.) revisa qué opinan otros usuarios del producto para poder tomar su decisión. Se ha usado en aplicaciones médicas, noticias, identificar la reputación, opiniones, emociones, y muchas otras aplicaciones. De ahí que las aplicaciones para explotar la información que se genera de la categorización de datos ha tenido mucha importancia en los últimos años.

Para hacer aprendizaje máquina necesitamos:

  • Datos. Si queremos identificar imágenes de gatos, necesitaremos muchas imágenes con y sin gatos.
  • Ejemplos de los resultados esperados. Etiquetas diciendo si en la imagen hay un gato.
  • Una manera de medir el desempeño del algoritmo. Debemos saber si lo está haciendo bien o mal y hacer ajustes apropiados. A esto se le llama aprender.

Nunca hay que olvidar que lo único que le interesa al algoritmo de aprendizaje es mejorar su desempeño. No le importa si hace la tarea como los humanos esperamos que la haga. El desempeño se mide mediante la función de pérdida que es la que asigna un valor que indica qué tan bien está haciendo la tarea el modelo. Entonces el modelo sólo quiere disminuir la función de pérdida. Para aprender a clasificar se usan los datos de entrenamiento que tienen las respuestas y el modelo aprende transformaciones que facilitan la clasificación de los datos vistos. Pero queremos que nuestro modelo sea capaz de clasificar ejemplos que nunca ha visto antes, no sólo ejemplos en los que fue entrenado. A este proceso se le llama generalizar.

Al entrenar un modelo, minimizamos el error en el conjunto de entrenamiento con la esperanza de que al mismo tiempo se reduzca el error en el conjunto de prueba. Para que esto pase, el conjunto de entrenamiento y el conjunto de prueba deben ser independientes e idénticamente distribuidos. Cosa que generalmente es difícil asegurar.

El reto de un algoritmo de entrenamiento es cumplir con 1. Minimizar el error en el entrenamiento 2. Minimizar la diferencia de error en el entrenamiento y la prueba.

Si un modelo no cumple con el punto uno se dice que tiene subajuste (underfiting) y si no cumple con el punto dos se dice que tiene sobreajuste (overfittig).

La mejor práctica es dividir el conjunto de datos en tres, entrenamiento, validación y prueba. El modelo aprende del conjunto de entrenamiento, se evalúa en el conjunto de validación y si no estamos contentos con el resultado, volvemos a entrenar. Cuando tenemos un desempeño aceptable en el conjunto de validación, podemos dejar de entrenar y tendremos un modelo terminado. El conjunto de prueba nunca debe usarse para la toma de decisiones, únicamente para evaluar de forma definitiva el modelo y compararlo con alternativas. La manera más común es usar 80% para el entrenamiento y 10% para validación y prueba.

Medidas de evaluación

Las métricas de evaluación comúnmente usadas en clasificación de texto son precisión (precision, del inglés), recall y medida-F (F1, F-score, F- measure). Estas medidas reflejan la importancia de recuperar los ejemplos positivos en la clasificación.

  • TP: True positive (ejemplo clasificado correctamente como positivo).
  • FP: False positive (ejemplo clasificado como positivo por el sistema pero que en realidad era negativo).
  • TN: True negative (ejemplo correctamente clasificado como negativo)
  • FN: False negativo (ejemplo clasificado como negativo por el sistema pero que en realidad era positivo).

Precisión

Es el número de ejemplos positivos clasificados correctamente dividido por el número de ejemplos etiquetados por el sistema como positivos.

\[ Precision = \frac{TP}{TP+FP}\]

Recall

Es el número de ejemplos positivos clasificados correctamente dividido por el número de ejemplos positivos en los datos.

\[ recall = \frac{TP}{TP+FN}\]

F-score (F-measure, F1)

Es la media harmónica de la precisión y recall.

\[ F_1=2\frac{precision\times recall}{precision + recall}\]

Accuracy

El accuracy es otra medida también usada para evaluar el desempeño de los sistemas de clasificación en las competencias de clasificación de texto, aunque se prefiere F1, ya que es la combinación de precisión y recall, lo cual nos da una mejor guía del desempeño del clasificador.

El accuracy representa la efectividad general del sistema clasificador. Sin embargo, si el clasificador está sesgado hacia la clase negativa, es decir, no reconoce la clase de interés, con esta métrica dará un valor alto, puesto que la clase que no es de interés también se incluye en esta medida. Por ejemplo, en un sistema clasificador de textos agresivos, si los datos están desbalanceados es decir, hay más ejemplos de textos no agresivos (3,000), en contraste con ejemplos que sí son agresivos (800); generalmente los modelos aprende la clase más poblada, en este caso la clase que no es agresiva; no obstante, al predecir nuevos datos, los ejemplos negativos (true negative) sesgarán la medida y se obtendrá un buen desempeño, pero en realidad no es que reconozca muy bien los ejemplos agresivos (true positive), esto debido a la métrica.

\[ Acuracy= \frac{TP+TN}{TP+FN+FP+TN}\] En competencias internacionales en tareas de clasificación como SemEval, IberLef, MexLef, entre otras, se prefieren métricas como F1-score, precisión y recall para ser objetivos en el desempeño de los sistemas clasificadores.

Métricas Promedio: Micro- Macro (Micro- Macro average)

Si el clasificador es multiclase hay dos tipos de promedio de métricas que afectan cuando los datos están desbalanceados.

Micro average:

\[Precision_{micro}=\frac{TP_{clase-1} + TP_{clase-2}+\cdots +TP_{clase-n}}{TP_{clase-1}+FP_{clase-1}+\cdots+TP_{clase-n}+FP_{clase-n}}\]

\[Recall_{micro}=\frac{TP_{clase-1} + TP_{clase-2}+\cdots +TP_{clase-n}}{TP_{clase-1}+FN_{clase-1}+\cdots+TP_{clase-n}+FN_{clase-n}}\]

\[ F_1=2\frac{precision_{micro}\times recall_{micro}}{precision_{micro} + recall_{micro}}\]

Macro average:

\[ Precision_{macro} = \frac1n\sum_{i=1}^{n}Precision_{clase-i}\]

\[ Recall_{macro} = \frac1n\sum_{i=1}^{n}Recall_{clase-i}\]

\[ F1_{macro} = \frac1n\sum_{i=1}^{n}F1_{clase-i}\]

DATOS DE ENTRENAMIENTO Y PRUEBA

Como ya vimos anteriormente, hay tres fases en el proceso de clasificación, a saber, la etapa de entrenamiento, la etapa de validación o prueba (evaluación del modelo), y la etapa de predicción (predicción nuevos datos). En la etapa de entrenamiento, el modelo es entrenado con los datos de entrada. En esta etapa los datos se preprocesan y los parámetros del modelo se ajustan. Es importante que los datos de entrada contengan los suficientes ejemplos para cada clase que se quiere predecir, puesto que esto influirá en la construcción del modelo. Es decir, procurar que las clases estén balanceadas, es decir, que contenga aproximadamente, la misma cantidad de ejemplos por cada clase.

Por ejemplo, si se desea crear un clasificador que identifique mensajes si son agresivos o no (un clasificador binario), los datos para el entrenamiento deben tener ejemplos tanto de textos agresivos como no agresivos. Generalmente, en este tipos de problemas, se cuenta con menos ejemplos de la clase positiva, en este caso, de ejemplos agresivos (clase positiva) que de ejemplos no agresivos (clase negativa). A veces es recomendable reducir el número de ejemplos negativos del entrenamiento aunque se pierda diversidad del vocabulario que puedan proporcionar estos ejemplos. Lo que se recomienda es construir el modelo con la reducción y evaluar el modelo en el conjunto prueba. Otra opción es crear más ejemplos de la clase minoritaria de manera artificial.

K-iteraciones de Validación Cruzada (K-Fold CrossValidation)

La validación cruzada es una técnica para evaluar los resultados de un análisis estadístico. En el caso cuando se tiene un conjunto de datos de entrenamiento y otro de prueba, se entrena el modelo en el entrenamiento y se evalúa con el de prueba o validación. En este caso, hemos realizado solo una prueba del desempeño del clasificador.

La técnica de validación cruzada nos permite repetir la evaluación del clasificador y calcular la media aritmética de las medidas de evaluación (precisión, recall, F1, etc) sobre diferentes particiones de los datos.

Por ejemplo, K-Fold cross-validation con \(k=3\), se toma el conjunto de datos \(T\) (entrenamiento, o la unión de entrenamiento y test, para tener más ejemplos) y se divide en tres partes \((P_1,P_2,P_3)\) con las clases balanceadas y sin repetición de los ejemplos. El proceso de evaluación se repite 3 veces. En cada iteración, se entrena con dos partes y se evalúa con la tercer parte, es decir en iteración 1 se entrena con \(P_1\) y \(P_2\) y se evalúa con \(P_3\). Después se entrena con \(P_1\) y \(P_3\) y se evalúa con \(P_2\). Finalmente, se entrena con \(P_2\) y \(P_3\) y se evalúa con \(P_1\). El desempeño general del clasificador es la media de las métricas obtenidas en cada iteración.
